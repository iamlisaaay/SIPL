# Специфікація мови SIPL (версія 1.0)

Канонічна машинозчитувана граматика: [`src/sipl/grammar/sipl.lark`](../src/sipl/grammar/sipl.lark).
Цей документ пояснює її і фіксує відповідність БНФ курсу.

## 1. БНФ курсу (ядро, діалект `core`)

| Метазмінна | Категорія | Позначення |
|---|---|---|
| `<програма>` | Prog | P |
| `<оператор>` | Stm | S |
| `<вираз>` | Aexp | a |
| `<умова>` | Bexp | b |
| `<змінна>` | Var | x |
| `<число>` | Num | n |

```text
P ::= begin S end                                                     NP1 / P1
S ::= x := a | S1 ; S2 | if b then S1 else S2 | while b do S
    | begin S end | skip                                              NS1–NS6 / S1–S6
a ::= n | x | a1 + a2 | a1 - a2 | a1 * a2 | (a)                       NA1–NA6 / A1–A6
b ::= a1 = a2 | a1 > a2 | b1 ∨ b2 | ¬ b | (b)                         NB1–NB5 / B1–B5
x ::= ... | M | N | ...                                               NV
n ::= ... | -1 | 0 | 1 | 2 | ...                                      NN
```

Кожна альтернатива позначена в `sipl.lark` коментарем з іменем правила (`// S3`), а тест
`test_grammar_mentions_all_bnf_rules` перевіряє, що жодне правило не пропущено.

## 2. Як знято неоднозначність

БНФ курсу неоднозначна (`S ::= S;S`, `a ::= a+a`). Граматика Lark задає ту саму мову,
але з однозначним розбором:

| Конструкція | Рішення | Обґрунтування |
|---|---|---|
| `;` | послідовність `stmt (; stmt)*`; у дереві виводу – ліво-вкладені `NS2` | композиція асоціативна |
| `while b do S`, `if ... else S` | тіло – **один** оператор | оператор циклу має вищий пріоритет, ніж послідовне виконання |
| `+ -` проти `* div mod` | множення сильніше; усе лівоасоціативне | звичайна арифметика |
| `∨` проти `∧` проти `¬` | `¬` найсильніше, далі `∧`, далі `∨` | `¬M = N` означає `¬(M = N)` |
| `(` | дужка виразу або умови; розбір Earley обирає ту, з якою речення коректне | `(X + 1) > 2` і `(X > 2)` обидва допустимі |

`if` завжди має `else`, тому проблеми «висячого else» немає.

## 3. Лексика

| Лексема | Запис | Примітки |
|---|---|---|
| ключові слова | `begin end if then else while do skip` | лише малими літерами |
| змінна | `[A-Za-z_][A-Za-z0-9_]*` | регістр має значення, ключове слово не може бути змінною |
| число | `[0-9]+`; від'ємне – `-` перед числом у позиції операнда | `X - -1` допустимо, `-X` – ні (немає в БНФ) |
| присвоювання | `:=` | |
| арифметика | `+`, `-` (також `−`, `–`), `*` (також `∗`, `×`) | |
| порівняння | `=`, `>` | |
| логіка | `∨` / `or` / `\/`, `¬` / `not` / `~` | словесні форми розпізнаються як цілі слова (`order` – змінна) |
| коментар | `// до кінця рядка` | ігнорується, як і пробільні символи |

## 4. Розширення SIPL-ext (діалект `ext`, за замовчуванням)

На практиках у задачах є `≥`, `div`, `mod`, тому ці конструкції підтримано як
**явно позначене розширення**. Прапорець `--strict` (діалект `core`) відхиляє їх
з діагностикою `E201` і точною позицією.

| Конструкція | Запис | Функція терму |
|---|---|---|
| `a1 >= a2` | `>=`, `≥` | `gre` |
| `a1 < a2` | `<` | `ls` |
| `a1 <= a2` | `<=`, `≤` | `lse` |
| `a1 != a2` | `!=`, `≠`, `<>` | `neq` |
| `b1 ∧ b2` | `∧`, `and`, `/\`, `&` | `and` |
| `a1 div a2`, `a1 mod a2` | `div`, `mod` | `div`, `mod` |
| `true`, `false` | | константи |

**Ділення** – евклідове, як у SMT-LIB: `a = b·(a div b) + (a mod b)`, `0 ≤ a mod b < |b|`.
Тому семантика інтерпретатора й асистента доведення (Z3) збігається. `div 0` і `mod 0`
невизначені.

## 5. Мова специфікацій (лише для `sipl prove`)

Формули передумов, післяумов та інваріантів – це умови SIPL-ext, до яких додано:

* імплікацію `→` / `->` (найслабша, правоасоціативна);
* виклики функцій `pow(x, n)`, `fact(n)`, `gcd(a, b)`, `abs(a)`, `min(a, b)`, `max(a, b)`.

У програмах ці конструкції заборонені (діагностика `E202`).
