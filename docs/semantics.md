# Семантика: терми та їх обчислення

## 1. Побудова семантичного терму (SEM-01)

Перетворення `sem_P : Prog → TFS`, `sem_S : Stm → TFS`, `sem_A : Aexp → TFA`,
`sem_B : Bexp → TFB` задаються рекурсивно за структурою AST
([`build.py`](../src/sipl/semantics/build.py)). Правила:

| Правило | Схема |
|---|---|
| NS_Prog | `sem_P(begin S end) = sem_S(S)` |
| NS_Stm_As | `sem_S(x := a) = AS^x(sem_A(a))` |
| NS_Stm_Seq | `sem_S(S1; S2) = sem_S(S1) · sem_S(S2)` |
| NS_Stm_If | `sem_S(if b then S1 else S2) = IF(sem_B(b), sem_S(S1), sem_S(S2))` |
| NS_Stm_Wh | `sem_S(while b do S) = WH(sem_B(b), sem_S(S))` |
| NS_Stm_BE | `sem_S(begin S end) = (sem_S(S))` |
| NS_Stm_skip | `sem_S(skip) = id` |
| NS_A_Num, NS_A_Var | `sem_A(n) = n`, `sem_A(x) = x⇒` |
| NS_A_Add/Sub/Mult | `sem_A(a1 ∘ a2) = S2(add/sub/mult, sem_A(a1), sem_A(a2))` |
| NS_B_eq/gr/or | `S2(eq/gr/or, ...)` |
| NS_B_neg | `sem_B(¬b) = S1(neg, sem_B(b))` |

Для розширень діють аналогічні правила (`gre`, `ls`, `lse`, `neq`, `and`, `div`, `mod`).
Повний список можна вивести командою `sipl term - --rules`.

Правила NS_A_Par і NS_B_Par не застосовуються явно, бо дужки в AST не зберігаються:
вони впливають лише на структуру дерева.

**Пояснення побудови** (`--explain`) робить те саме, що й вручну. Беремо
`sem_P(<текст>)` і щоразу замінюємо найлівішу неперекладену частину `sem_X(...)` правою
частиною відповідного правила, доки таких частин не залишиться.

**Дужки блоку.** `ParenT` (результат NS_Stm_BE) друкується з дужками, лише коли блок
стоїть усередині композиції: `AS^A(1) · (AS^B(2) · AS^C(3))`. Як аргумент `WH` чи `IF`
блок друкується без дужок.

**Зв'язок із джерелом.** Кожен вузол терму зберігає `origin` – `SourceSpan` вузла AST,
з якого його побудовано.

## 2. Обчислення терму на стані (SEM-02)

[`evaluate.py`](../src/sipl/semantics/evaluate.py) застосовує терм до стану й записує
у трасу формулу, використану на кожному кроці:

| Формула | Зміст |
|---|---|
| AF_S | `Sn(f, g1, ..., gn)(st) = f(g1(st), ..., gn(st))` |
| AF_AS | `AS^x(fa)(st) = st ∇ [x ↦ fa(st)]` |
| AF_SEQ | `(f1 · f2)(st) = f2(f1(st))` |
| AF_IF | `IF(fb, f1, f2)(st) = f1(st)`, якщо `fb(st) = true`, і `f2(st)`, якщо `false` |
| AF_WH | `WH(fb, fs)(st) = st_n`, де `st_{i+1} = fs(st_i)`, `fb(st_0..st_{n-1}) = true`, `fb(st_n) = false` |
| AF_DNM | `x⇒(st) = st(x)` |
| AF_ID | `id(st) = st` |

Стани нумеруються `st`, `st1`, `st2`, ... у порядку появи. Формат запису
`[X ↦ 5, Y ↦ 2]` і перекриття `∇`: наявні імена зберігають
позицію, нові дописуються в кінець.

### Результати

| Статус | Коли | Код CLI |
|---|---|---|
| `defined` | отримано кінцевий стан | 0 |
| `undefined` | `x⇒(st)` для відсутньої змінної, `div`/`mod` на нуль | 3 |
| `limit` | вичерпано ліміт ітерацій; незавершуваність загалом нерозв'язна, тому це «невідомо» | 4 |

Невизначеність поширюється за суперпозицією: якщо аргумент невизначений, невизначене
й значення функції. Логічні `or`/`and` теж строгі (як `S2`), а не ліниві.
