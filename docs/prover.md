# Асистент доведення коректності (SEM-04)

## 1. Що доводиться

Для програми P, передумови `pre` і післяумови `post`:

* **часткова коректність**: для кожного st, де виконується pre, якщо `sem_P(P)(st)↓ = st'`,
  то в st' виконується post;
* **повна коректність**: для кожного такого st значення `sem_P(P)(st)` визначене і в
  ньому виконується post.

Це формулювання теорем 1.3 і 1.4 підручника: `∀st (termination ⇒ correctness)` і
`∀st (termination ∧ correctness)`.

Вільні змінні формул – це змінні програми (`X`, `R`) і логічні константи (`x`, `y`) для
початкових значень. Усі вони неявно квантифіковані загальним квантором.

## 2. Від індукції курсу до умов перевірки

У практикумі коректність циклу доводять **індукцією за кількістю ітерацій** k
(`NumItWH`). Асистент робить те саме, але формулює твердження індукції як
**інваріант** I – властивість кожного стану `st_k`. Тоді доведення розпадається на
скінченну кількість формул (умов перевірки, VC), які генерує
[`vcgen.py`](../src/sipl/prover/vcgen.py) через найслабші передумови `wp`:

| VC | Формула | Частина доведення в курсі |
|---|---|---|
| `init` | `pre → wp(P, post)` | **база індукції**: перед першою ітерацією (k = 0) інваріант істинний |
| `preserve` | `I ∧ b → wp(S, I)` | **крок індукції** k → k+1: тіло fs переводить st_k у st_{k+1} |
| `exit` | `I ∧ ¬b → Q` | вихід: `fb(st_k) = false`, і з інваріанта випливає потрібне далі |
| `defined` | `I → b визначена` | лише коли в умові є `div`/`mod` |
| `bound` | `I ∧ b → V ≥ 0` | повна коректність: варіант обмежений знизу |
| `decrease` | `I ∧ b ∧ V = v₀ → wp(S, V < v₀)` | повна коректність: варіант строго спадає |

`bound` і `decrease` – це аргумент із теореми 1.4. Послідовність `V(st_0) > V(st_1) > ...`
невід'ємних цілих не може бути нескінченною, отже цикл завершується.

Правила `wp`:

```text
wp(skip, Q)                 = Q
wp(x := a, Q)               = def(a) ∧ Q[a/x]
wp(S1; S2, Q)               = wp(S1, wp(S2, Q))
wp(begin S end, Q)          = wp(S, Q)
wp(if b then S1 else S2, Q) = def(b) ∧ (b → wp(S1, Q)) ∧ (¬b → wp(S2, Q))
wp(while b do S, Q)         = I     (+ умови циклу з таблиці вище)
```

`def(a)` вимагає ненульових дільників для `div`/`mod`.

**Вкладені цикли.** Умови внутрішнього циклу мають виконуватися в контексті тіла
зовнішнього. Тому вони вбудовуються в `wp` зовнішнього тіла, а змінні, які
внутрішній цикл змінює, перейменовуються на свіжі (`S'0`, `J'0`). Це квантор
загальності в позитивній позиції формули, яку перевіряють на загальнозначущість.
Так факти про незмінні змінні (зокрема `v₀` варіанта зовнішнього циклу) зберігаються
автоматично.

## 3. Перевірка умов

[`solver.py`](../src/sipl/prover/solver.py):

1. **Z3** (SMT, цілі числа). Заперечення VC незадовільне – отже, VC доведено для
   **всіх** цілих значень. Функції специфікацій – неінтерпретовані функції з
   аксіомами-визначеннями: `pow(x,0)=1`, `n>0 → pow(x,n)=x·pow(x,n-1)`, аналогічно
   `fact`, а для `gcd` – рекурсія Евкліда для додатних аргументів.
2. Якщо Z3 знайшов модель, асистент **перераховує** формулу на цих значеннях зі
   справжніми функціями. Аксіоми не визначають, наприклад, `pow` з від'ємним
   показником, тому без цієї перевірки модель могла б бути хибним контрприкладом.
3. Якщо Z3 відповів `unknown` або не встиг за 4 с (нелінійна арифметика), запускається
   **обмежений перебір** значень змінних. Він може знайти контрприклад, але довести
   умову не може, тому статус лишається «не вирішено» і вказується кількість
   перебраних наборів.

## 4. Висновки асистента

| Висновок | Коли |
|---|---|
| ДОВЕДЕНО (`proved`) | Z3 довів усі умови перевірки |
| СПРОСТОВАНО (`refuted`) | є конкретний вхідний стан, на якому програма порушує специфікацію (тестування або відтворення `init`) |
| НЕ ДОВЕДЕНО (`not_proved`) | якась умова хибна, але програма на перевірених входах працює правильно; найчастіше інваріант чи варіант занадто слабкий |
| НЕ ВИРІШЕНО (`unknown`) | частину умов не вдалося ні довести, ні спростувати |

## 5. Контрприклади та їх відтворення

Знайдений контрприклад відтворюється на **семантичному терміні**:

* `preserve`: тіло циклу `fs` застосовується до стану st, показується `fs(st)` і
  те, що `I(fs(st)) = false`;
* `decrease`: показуються `V(st)` і `V(fs(st))`;
* `init`: програма запускається з початкового стану, і показується, що післяумова
  хибна (або що інваріант просто не випливає з передумови).

Крім того, асистент **тестує** програму: перебирає початкові стани з невеликими
значеннями, що задовольняють `pre`, застосовує до них `sem_P(P)` і перевіряє `post`.
Для повної коректності незавершення в межах ліміту теж рахується як провал.

## 6. Формат специфікації

```toml
pre  = "X = x ∧ Y = y ∧ y >= 0"
post = "R = pow(x, y)"
mode = "total"                 # або "partial"; за замовчуванням total, якщо в усіх циклів є variant

[[loop]]                       # по одній таблиці на кожен while у порядку тексту
invariant = "R * pow(X, Y) = pow(x, y) ∧ Y >= 0 ∧ X = x"
variant   = "Y"
# line = 5                     # або прив'язка до циклу за номером рядка

[testing]

```

## 7. Межі автоматизації

* Задача верифікації в цілому нерозв'язна: асистент **не шукає** інваріанти, їх задає людина.
* Слабкий інваріант дає «спростовано» або «не вирішено» навіть для правильної програми.
  Контрприклад до `preserve` означає лише, що **інваріант** не зберігається, а не обов'язково
  що програма неправильна. Відтворення на терміні допомагає розрізнити ці випадки.
* Нелінійна арифметика (`R * pow(X, Y)`, `n * (n + 1)`) розв'язується Z3 евристично.
  На всіх прикладах із `examples/` вона працює, але загалом гарантії немає.
* Вважається, що всі вхідні змінні мають значення в початковому стані.
* Підтримуваний клас: програми SIPL (зокрема з вкладеними циклами), формули з
  `+ - * div mod`, порівняннями, логічними зв'язками та функціями з п. 3.
